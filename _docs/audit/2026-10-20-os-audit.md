# Z and Z OS Audit, 2026-10-20

**Scope:** the whole system as it runs in production today: website lead capture, the admin OS, communications, crons, database, security, and the code on every branch.
**Method:** live reads of Vercel (deployments, env var names, runtime errors), read-only aggregate queries against the production Supabase database (counts only, no customer details), a full typecheck/lint/build, and a file-by-file code review of every backend route.

---

## 1. The state of things in one paragraph

The code is healthy: it typechecks, lints, and builds clean, production has had zero runtime errors in the last 7 days, and every database migration (001 to 015) is applied. The website is doing its job and lead volume roughly tripled after the summer. The problem is that the back office has been idle since July 23. Nobody has opened a lead, moved a job, or sent an invoice from the OS in three months; 50 web leads sit in New. Texting, the review engine, and speed-to-lead escalation are all still switched off because the Twilio account, the cron secret, and the Google review link were never set up. And a large batch of work from July and August is stranded, uncommitted, on an old branch in the main checkout.

## 4. Findings and fixes

Severity: **C** critical, **H** high, **M** medium, **L** low. Status refers to this audit branch; nothing is live until it is merged and deployed.

### Security

| Sev | Finding | Status |
|---|---|---|
| C | **Admin pages were readable without logging in.** Login was only checked in the `(authed)` layout, and Next skips shared layouts on client-side navigation, so a crafted RSC request rendered any admin page (customers, jobs, invoices, messages) with no session. Reproduced locally against a production build. Writes were never exposed: every `/api/admin` route checks the session itself. | Fixed: `proxy.ts` now verifies the sealed session cookie for every `/admin/*` and `/field/*` request before anything renders. Covered by `tests/admin-auth-gate.test.mjs`. |
| H | **Nobody has the current admin password.** | Fixed: `scripts/reset-admin-password.mjs` sets a new one (hidden prompt, stores only the bcrypt hash in Vercel). Takes effect on the next production deploy. |
| H | Login throttle was in memory, so each serverless instance kept its own count. | Fixed: shared `login_attempts` ledger (migration 016) with a per-IP and a global cap; memory fallback until 016 is applied. |
| H | One shared password for the office and the field phones; no way to end sessions short of rotating `SESSION_SECRET`, which also breaks every invoice link. | Open: per-crew logins and a session version check. Follow-up. |
| M | Twilio inbound webhook accepted unsigned requests when the auth token was missing (true in production today): anyone could inject inbox messages or clear opt-outs. | Fixed: fails closed in production. |
| M | RLS off on eight tables (invoice history, estimates, pricebook, materials, knowledge docs, API usage). Not exploitable today because the anon key is never published, but one leak away. | Fixed in migration 016. **Needs applying in the Supabase SQL editor.** |
| M | Assistant prompt injection: customer-typed text reaches the model through tool results, and replies rendered any link as clickable. | Fixed: untrusted-data rule in the system prompt; external links clickable only for an allowlist of hosts. |
| M | Public lead endpoint had no bot protection. | Fixed: honeypot field, length caps, US-only phone numbers, duplicate-submit folding. Still recommended: a Vercel Firewall rate-limit rule on `/api/lead/`. |
| L | Photo validation accepted any `image/*` (including SVG) and trusted the filename extension. | Fixed: exact type allowlist, extension derived from type. |
| L | No security headers. | Fixed: `frame-ancestors 'none'`, nosniff, referrer policy, permissions policy. |
| L | Unescaped "preferred callback time" in the dispatch email; inbox thread filter built from raw input. | Fixed. |

### Lead intake and communications

| Sev | Finding | Status |
|---|---|---|
| H | **Cron paths had no trailing slash** while the site forces one with a 308 redirect, so Vercel Cron may never have reached either handler. The Twilio status callback had the same problem, which would also break signature checks. | Fixed in `vercel.json`, the review sender, and `WIRING.md`. |
| H | **Escalation cron would starve:** it took the 25 oldest leads without skipping ones already fully escalated, so the July backlog would fill every batch and new leads would never escalate. | Fixed: skips fully-escalated leads and ignores leads older than 72 hours. |
| H | **A phone photo over 4.5MB lost the whole lead** (Vercel rejects the body before our code runs). | Fixed: photos are resized in the browser, and a too-large upload is retried without the photo. |
| H | **SMS consent box was pre-ticked.** Not valid opt-in for A2P or TCPA. | Fixed: unticked by default. The 17 existing "yes" rows should not be used for marketing texts. |
| H | Out-of-area leads from the contact page were never flagged (only the booking form checked the ZIP). | Fixed: the server flags out-of-area from the ZIP for every form. |
| H | Spam leads could not be deleted (foreign key from `sms_consent.job_id`). | Fixed: migration 016 plus the delete route clearing references. |
| M | The quick lead form sent "declined SMS" without asking, overwriting a returning customer's earlier opt-in. | Fixed: forms that don't ask send no answer, and the ledger is left alone. |
| M | Review texts could send at any hour (backlog, retries) and failed sends retried forever. | Fixed: sends only 11am to 6pm Pacific; cancelled after 3 failed attempts. |
| M | Twilio status callback pointed at a route that did not exist. | Fixed: route added (ported from the stranded branch). |
| M | A lead matched by email dropped its new phone number. | Fixed: fills a blank phone, notes a different one. |
| M | Review engine can't reach phone-in customers (consent is only captured on the web form). | Open: add a "customer agreed to texts" field to the admin job form. |
| L | Dispatch email linked to the job list instead of the job. | Fixed. |

### Admin workflows and money

| Sev | Finding | Status |
|---|---|---|
| H | Dashboard, analytics, and customer pages read money only from `invoice_history` (empty by design), so open balance showed $0 with two unpaid invoices and revenue would read $0 forever. | Fixed: computed from `invoices` (plus legacy history); paying an invoice updates customer lifetime revenue, jobs, and last-job date. |
| H | Invoices with no job could never be sent or marked paid. | Fixed: standalone send (email or text) and mark-paid, reachable from the invoices list. |
| H | "Move to Invoiced / Paid" buttons on a job skipped the invoice, so a customer could still be asked to pay a "paid" job. | Fixed: those states are reached only through invoicing and payment. |
| H | Invoicing jumped new or scheduled jobs straight to invoiced (skipping completion and the review request); paying one of several invoices marked the whole job paid. | Fixed: job money reconciles from all its invoices and only moves a job that is complete; mark-paid is idempotent (no duplicate receipts). |
| H | Spam leads and converted invoices couldn't be deleted; paid invoices could be. | Fixed: references cleared before delete; paid invoices are locked. |
| H | An expired coupon was still public (header and `/coupons/`), and end dates were stored a day early. | Fixed: live-only filter in Pacific time; `/coupons/` is noindex when empty. |
| H | Stored Stripe links were reused forever (they expire in 24 hours) and survived invoice edits. | Fixed (Stripe is not enabled in production yet). |
| M | New Job listed only 500 of 2,573 customers. | Fixed: searchable customer picker. |
| M | Customer phone, email, and address couldn't be edited anywhere. | Fixed: contact form on the customer page. |
| M | Search crashed on commas or parentheses. | Fixed: shared filter sanitizer. |
| M | Estimates: resending reset approved to sent, convert was allowed from draft, a double click could create two invoices, dates showed a day early. | Fixed. |
| M | Dashboard said "20 leads not contacted" when 50 were waiting. | Fixed: exact count. |
| M | Customer tracking page showed nothing complete for invoiced, paid, or paused jobs; success banners showed in red. | Fixed. |
| L | Field mode listed every open job for any date; dispatch hid inactive-crew jobs and showed cancelled ones; AI cost undercounted past 1,000 calls; stale HubSpot copy; silent form errors; jobs list had no search box. | Fixed. |
| L | Invoice links fell back to a hard-coded signing secret if `SESSION_SECRET` were missing; tracking links never expired. | Fixed: fails closed in production; new tracking links last 180 days. |
